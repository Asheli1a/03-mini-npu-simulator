# Mini NPU Simulator

2차원 숫자 배열로 표현된 패턴과 필터의 MAC 점수를 계산하는
Python 콘솔 프로그램입니다.

외부 라이브러리 없이 반복문으로 MAC 연산을 구현하고,
사용자 입력 및 JSON 데이터에 대해 판정과 성능 분석을 수행합니다.

## 1. 실행 환경

실행 확인 환경:

- Windows / PowerShell 5.1
- Python 3.15.2
- 외부 패키지 설치 불필요
- 사용한 표준 라이브러리: json, math, re, pathlib, time
- 테스트 도구: unittest

## 2. 파일 구성

```text
mini-npu-simulator/
├─ main.py
├─ data.json
├─ inspect_data.py
├─ test_main.py
└─ README.md
```

- main.py: 입력, 검증, MAC 계산, 판정, 성능 측정 및 결과 출력
- data.json: 제공된 원본 필터와 패턴 데이터
- inspect_data.py: 데이터 구조와 배열 크기 확인 도구
- test_main.py: 자동 테스트
- README.md: 실행 방법과 결과 리포트

## 3. 실행 방법

프로젝트 폴더에서 실행합니다.

```powershell
python main.py
```

메뉴:

- 1: 사용자 입력 모드
- 2: data.json 분석 모드
- 0: 종료

data.json은 main.py와 같은 폴더에 둡니다.
프로그램은 현재 터미널 위치가 아닌 main.py 위치를 기준으로 파일을 찾습니다.

자동 테스트:

```powershell
python -m unittest -v
```

데이터 구조 확인:

```powershell
python inspect_data.py
```

## 4. 사용자 입력 모드

3×3 필터 A, 필터 B, 패턴을 순서대로 입력합니다.
각 배열은 3줄이며 각 줄에 숫자 3개를 공백으로 구분합니다.

입력 예:

```text
0 1 0
1 1 1
0 1 0
```

열 개수가 다르거나 숫자로 변환할 수 없는 값이 있으면
오류가 발생한 행만 다시 입력받습니다.

nan과 inf 등 유한하지 않은 값도 입력 오류로 처리합니다.

필터 A와 B는 사용자가 지정하는 임의의 필터입니다.
계산 후 A/B/판정 불가와 각 필터의 점수를 출력합니다.

성능 표는 입력한 패턴과 필터 A에 대한 MAC 호출 시간을 표시합니다.
필터 두 개의 전체 판정 시간은 아닙니다.

## 5. JSON 분석 모드

filters에서 size_5, size_13, size_25 필터를 읽습니다.
patterns의 size_N_idx 형식 키에서 N을 추출하여 필터를 선택합니다.

검증 항목:

- 최상위 filters와 patterns의 자료형
- 케이스 키 형식과 지원 크기
- input과 expected의 존재 여부
- 정사각형 배열 여부와 숫자 자료형
- 유한하지 않은 실수 여부
- 키에 명시된 크기와 실제 배열 크기의 일치
- Cross와 X 필터의 존재 및 정규화 후 중복 여부

파일 로드나 최상위 구조 검증이 실패하면 안내 후 메뉴로 돌아갑니다.
개별 케이스의 데이터 오류는 해당 케이스를 FAIL로 기록하고
나머지 케이스 분석을 계속합니다.

## 6. 구현 요약

### MAC 계산

같은 위치에 있는 패턴 값과 필터 값을 곱하고 모두 더합니다.

```text
score = Σ pattern[row][column] × filter[row][column]
```

mac()은 검증된 배열을 받아 계산만 수행합니다.
calculate_score()는 배열 검증 후 mac()을 호출합니다.

### 라벨 정규화

- +, cross, Cross → Cross
- x, X → X
- 앞뒤 공백 제거 및 영문 대소문자 통일
- 지원하지 않는 라벨은 오류 처리

### 점수 비교 정책

```python
EPSILON = 1e-9
```

두 점수 차이의 절댓값이 EPSILON보다 작으면 UNDECIDED입니다.
차이가 정확히 EPSILON과 같으면 동점이 아닙니다.
동점이 아니면 점수가 더 높은 필터를 선택합니다.

UNDECIDED는 정답 라벨이 아닌 판정 상태로 취급합니다.

## 8. 결과 리포트

### JSON 판정 결과

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

전체 6개 중 3개 통과, 3개 실패입니다.

### 실패 원인 분석

1. 원본 6개 케이스에서는 데이터/스키마 오류가 보고되지 않았습니다.
2. expected의 +와 x는 각각 Cross와 X로 정규화했습니다.
3. 따라서 이번 실패는 원본 라벨 문자열의 표현 차이 때문이 아닙니다.
4. size_5_1은 두 점수가 약 0.9로, epsilon 기준에서 동점입니다.
5. size_13_2는 두 점수가 약 7.5로, epsilon 기준에서 동점입니다.
6. size_25_1은 두 점수가 약 4.9로, epsilon 기준에서 동점입니다.
7. 세 케이스 모두 실제 계산값의 차이가 1e-9보다 작습니다.
8. 프로그램은 정책에 따라 세 케이스를 UNDECIDED로 판정했습니다.
9. expected는 Cross 또는 X이므로 비교 결과는 FAIL입니다.
10. 이는 자동 테스트 실패와 구분되는 데이터 판정 불일치입니다.
11. 부동소수점의 미세한 차이를 근거로 강제로 승자를 정하지 않았습니다.
12. PASS 수를 늘리기 위해 원본 데이터나 epsilon을 변경하지 않았습니다.
13. 현재 점수 방식과 비교 정책으로는 세 케이스의 expected를 재현하지 못합니다.
14. 과제 기준을 유지하면서 실패 케이스와 원인을 그대로 보고했습니다.

### 성능 측정 방법

- 타이머: time.perf_counter_ns()
- 각 입력에 대해 준비 실행 5회 후 측정
- 크기별 1,000회 측정 후 산술평균 계산
- 측정 대상: 필터 하나에 대한 mac() 호출
- 파일 읽기, 배열 검증, 콘솔 출력 및 판정은 측정 구간에서 제외
- 함수 호출 및 타이머 관련 오버헤드는 남아 있음
- 3×3은 별도 고정 십자가 패턴과 필터 사용
- 5×5, 13×13, 25×25는 각 크기의 첫 유효 패턴과 Cross 필터 사용

### 시간 복잡도 분석

1. 입력 배열은 N행과 N열로 구성됩니다.
2. 바깥 반복문은 N번 실행됩니다.
3. 각 바깥 반복에서 안쪽 반복문은 N번 실행됩니다.
4. 따라서 필터 하나당 N²번의 곱셈·누적 덧셈을 수행합니다.
5. 값이 0인 위치도 생략하지 않고 계산합니다.
6. MAC 함수의 시간 복잡도는 O(N²)입니다.
7. 두 필터를 계산하면 MAC 횟수는 2N²이며 복잡도는 여전히 O(N²)입니다.
8. 표의 MAC 횟수는 필터 하나 기준이며 곱셈과 덧셈을 따로 센 값이 아닙니다.
9. 측정에서는 배열이 커질수록 평균 실행 시간이 증가했습니다.
10. 측정값만으로 복잡도를 증명한 것이 아니라 반복문 구조를 근거로 설명했습니다.
11. 작은 입력에서는 함수 호출과 타이머 오버헤드의 상대적 영향이 큽니다.
12. 따라서 실행 시간 비율이 원소 수 비율과 정확히 같을 필요는 없습니다.
13. mac() 자체가 사용하는 추가 공간은 O(1)입니다.
14. 패턴과 필터 배열의 저장 공간은 각각 O(N²)입니다.
15. 이 결과는 Python 순차 구현의 성능이며 실제 NPU 하드웨어 성능을 뜻하지 않습니다.
