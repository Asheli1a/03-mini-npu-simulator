# Mini NPU Simulator

2차원 숫자 배열로 표현된 패턴과 필터의 MAC 점수를 계산하는
Python 콘솔 프로그램입니다.

외부 라이브러리 없이 반복문으로 MAC 연산을 구현하고,
사용자 입력 및 JSON 데이터에 대해 판정과 성능 분석을 수행합니다.

## 1. 실행 환경

실행 확인 환경:

- Windows / PowerShell 5.1
- Python 3.15.2
- 외부 패키지 설치 불필요
- 사용한 표준 라이브러리: json, math, re, pathlib, time
- 테스트 도구: unittest

## 4. 사용자 입력 모드

3×3 필터 A, 필터 B, 패턴을 순서대로 입력합니다.
각 배열은 3줄이며 각 줄에 숫자 3개를 공백으로 구분합니다.

입력 예:

```text
0 1 0
1 1 1
0 1 0
```

열 개수가 다르거나 숫자로 변환할 수 없는 값이 있으면
오류가 발생한 행만 다시 입력받습니다.

nan과 inf 등 유한하지 않은 값도 입력 오류로 처리합니다.

필터 A와 B는 사용자가 지정하는 임의의 필터입니다.
계산 후 A/B/판정 불가와 각 필터의 점수를 출력합니다.

성능 표는 입력한 패턴과 필터 A에 대한 MAC 호출 시간을 표시합니다.
필터 두 개의 전체 판정 시간은 아닙니다.

## 6. 구현 요약

### MAC 계산

같은 위치에 있는 패턴 값과 필터 값을 곱하고 모두 더합니다.

```text
score = Σ pattern[row][column] × filter[row][column]
```

mac()은 검증된 배열을 받아 계산만 수행합니다.
calculate_score()는 배열 검증 후 mac()을 호출합니다.

### 라벨 정규화

- +, cross, Cross → Cross
- x, X → X
- 앞뒤 공백 제거 및 영문 대소문자 통일
- 지원하지 않는 라벨은 오류 처리

### 점수 비교 정책

```python
EPSILON = 1e-9
```

두 점수 차이의 절댓값이 EPSILON보다 작으면 UNDECIDED입니다.
차이가 정확히 EPSILON과 같으면 동점이 아닙니다.
동점이 아니면 점수가 더 높은 필터를 선택합니다.

UNDECIDED는 정답 라벨이 아닌 판정 상태로 취급합니다.

### 시간 복잡도 분석

1. 입력 배열은 N행과 N열로 구성됩니다.
2. 바깥 반복문은 N번 실행됩니다.
3. 각 바깥 반복에서 안쪽 반복문은 N번 실행됩니다.
4. 따라서 필터 하나당 N²번의 곱셈·누적 덧셈을 수행합니다.
5. 값이 0인 위치도 생략하지 않고 계산합니다.
6. MAC 함수의 시간 복잡도는 O(N²)입니다.
7. 두 필터를 계산하면 MAC 횟수는 2N²이며 복잡도는 여전히 O(N²)입니다.
8. 표의 MAC 횟수는 필터 하나 기준이며 곱셈과 덧셈을 따로 센 값이 아닙니다.
9. 측정에서는 배열이 커질수록 평균 실행 시간이 증가했습니다.
10. 측정값만으로 복잡도를 증명한 것이 아니라 반복문 구조를 근거로 설명했습니다.
11. 작은 입력에서는 함수 호출과 타이머 오버헤드의 상대적 영향이 큽니다.
12. 따라서 실행 시간 비율이 원소 수 비율과 정확히 같을 필요는 없습니다.
13. mac() 자체가 사용하는 추가 공간은 O(1)입니다.
14. 패턴과 필터 배열의 저장 공간은 각각 O(N²)입니다.
15. 이 결과는 Python 순차 구현의 성능이며 실제 NPU 하드웨어 성능을 뜻하지 않습니다.

## 10. 과제 목표 6개 해설

심화 읽기: [MAC과 하드웨어 가속: CPU SIMD·Pascal CUDA·Tensor Core·NPU 비교](docs/mac-hardware-acceleration.md)

기존 CPU/GPU도 MAC을 병렬 처리한다는 점과, 전용 행렬 가속기의 데이터 재사용·정밀도·호출 비용 차이를 연결해 설명한다.
심화 자료는 설명 문서이며 제출 프로그램에 외부 가속 라이브러리를 추가하지 않는다.

### 1) MAC은 무엇이고 AI에서 왜 중요한가?

MAC은 Multiply-Accumulate, 즉 `s = s + x * w`를 반복하는 계산이다.
입력 x와 가중치 w를 곱해 누적합 s에 반영한다.
신경망의 선형 계층과 합성곱 등은 이러한 가중합을 대량으로 수행한다.
이번 구현의 핵심은 다음 한 줄이다.

```python
score += pattern[row][column] * filter_matrix[row][column]
```

MAC은 계산 패턴이며 NPU에만 존재하는 명령이 아니다.
Python의 곱셈 뒤 덧셈은 단일 반올림의 하드웨어 FMA와 동일하지 않다.
AI 전체가 MAC만으로 구성되는 것도 아니다. 활성화·정규화·softmax 등도 필요하다.

내 말로 설명하기:
> 입력과 가중치의 곱을 계속 더해 하나의 점수를 만드는 것이 MAC이다.
> 이 단순한 계산을 매우 많이 반복하는 점이 전용 행렬 가속기를 사용하는 이유다.

### 2) 패턴과 필터를 곱하고 더하면 어떻게 점수가 되는가?

수식은 `S(P,F) = Σ_i Σ_j P[i][j] * F[i][j]`이다.
배열을 길이 N²의 벡터로 펼쳤다고 생각하면 두 벡터의 내적이다.
필터 가중치가 큰 위치에 큰 입력이 들어오면 점수 기여가 커진다.
이진 3×3 십자가끼리는 활성 위치 5곳이 겹쳐 5점이고,
십자가와 X는 중심만 겹쳐 1점이다.

이 점수는 확률이나 정규화된 유사도 백분율이 아니다.
필터의 가중치 크기에도 영향을 받는다.
이번 원본 데이터처럼 서로 다른 모양의 필터에서 동점이 날 수도 있다.
동점 처리 때문에 FAIL이 나왔다고 점수식을 임의로 정규화하지 않았다.

내 말로 설명하기:
> 같은 위치끼리 곱한 값을 모두 더한다. 모양뿐 아니라 필터 가중치도 결과를 바꾼다.

### 3) JSON 키·라벨 규칙과 정규화 이유는?

`size_13_2`의 13은 한 변의 길이이고 2는 케이스 식별 번호이다.
키에서 N을 추출해 `filters['size_13']`을 선택한 다음 실제 배열 크기도 검증한다.
키에 13이라고 쓰였다고 실제 데이터도 13×13이라고 믿어서는 안 된다.

- filter의 cross와 expected의 +는 모두 Cross로 변환한다.
- x와 X는 X로 변환한다.
- 앞뒤 공백과 영문 대소문자를 정리한다.
- 알 수 없는 라벨, 정규화 후 중복 필터는 오류로 처리한다.

내 말로 설명하기:
> 같은 뜻의 외부 표기를 내부의 한 가지 라벨로 통일해야 문자열 차이로 오판하지 않는다.

### 4) 부동소수점 오차와 epsilon은?

많은 십진 소수는 이진 float로 정확히 표현되지 않는다.
수학적으로 같은 합도 연산 순서와 반올림에 따라 조금 다르게 표현될 수 있다.
실제 데이터에서는 7.50 대 7.50이 float에서 7.499999999999997 대 7.5로 표시된다.

정책은 `abs(a - b) < 1e-9`이면 UNDECIDED이다.
차이가 정확히 1e-9이면 동점이 아니다.
epsilon은 산술 정밀도를 높이는 기능이 아니라 판정 정책이다.
모든 데이터 규모에 보편적인 최적 epsilon이 있는 것은 아니다.
이번 과제는 고정 절대오차를 사용하며 상대오차 정책으로 임의 변경하지 않았다.
무한대·NaN은 동점이 아니라 수치 오류로 처리한다.

내 말로 설명하기:
> 작은 표현 오차로 승자를 잘못 고르지 않게 허용 범위를 정한다.
> 이번 세 사례는 정확한 십진 계산부터 동점이므로 오차를 없애도 정답 라벨을 고를 수 없다.

### 5) 크기별 측정과 O(N²)의 근거는?

바깥 반복문 N회와 안쪽 반복문 N회로 모든 원소를 방문한다.
필터 하나는 N² MAC, 두 개는 2N² MAC이다.
상수 계수를 제외하면 시간 복잡도는 O(N²)이다.
한 변 N이 두 배면 원소 수는 네 배이다.
전체 원소 수 M=N²를 기준으로 표현하면 O(M), 즉 원소 수에 선형이다.
이는 지수적 증가가 아닌 이차 증가이다.

곱셈 하나와 덧셈 하나를 별개로 세는 연산량 표기에서는 1 MAC을 2연산으로 센다.
이 프로젝트의 표는 MAC 횟수를 세므로 25×25는 625이며 1250이 아니다.
MAC 함수는 추가 메모리 O(1), 배열 자체 저장은 O(N²)이다.
JSON 전체 저장 공간은 모든 필터와 패턴을 합한 크기에 비례한다.

실측은 코드 구조의 복잡도 설명을 뒷받침할 뿐 그 자체가 증명은 아니다.
짧은 함수에서는 타이머, 함수 호출, 인터프리터 및 시스템 부하 영향이 크다.
서로 다른 PC나 다른 시점의 값으로 NPU 성능을 추정할 수 없다.

내 말로 설명하기:
> 모든 원소를 한 번씩 처리하므로 N을 기준으로 N²이다.
> 이론은 반복문으로 설명하고, 실험에서는 I/O를 제외한 반복 평균으로 경향을 확인한다.

### 6) 실패 원인을 어떻게 분리하는가?

| 원인 | 예 | 진단과 대응 |
|---|---|---|
| 데이터/스키마 | 필터 누락, 잘못된 크기·라벨 | 검증 후 케이스 FAIL, 원인 기록 |
| 로직 | 누적합·인덱스 오류 | 작은 손계산 예제로 재현 후 코드 수정 |
| 수치 계산 | 오버플로, NaN | 유한성 검사, 계산 오류 처리 |
| 비교 정책 | 미세한 차이로 승자 선택 | epsilon 경계 테스트 |
| 점수 방식의 한계 | 정확한 동점과 expected 불일치 | 독립 검산 후 UNDECIDED 및 한계 보고 |

자동 테스트 통과는 구현이 지정한 계약을 지킨다는 뜻이지 모든 패턴을 분류한다는 뜻이 아니다.
FAIL을 없애기 위해 데이터나 epsilon을 정답에 맞춰 조절하지 않는다.

내 말로 설명하기:
> 실패는 데이터, 계산 코드, 수치, 판정 정책 순서로 분해해서 확인한다.
> 정상 계산으로도 동점이면 버그를 고칠 문제가 아니라 현재 방식의 한계를 보고할 문제다.

## 11. MAC과 NPU·Tensor Core의 관계

상세 설명은 [별도 심화 문서](docs/mac-hardware-acceleration.md)로 분리했다.

- MAC은 연산 패턴, SIMD·CUDA 일반 연산·Tensor Core는 실행 방식 또는 경로다.
- CPU도 SIMD FMA를, Pascal GPU도 CUDA 병렬 계산과 일부 INT8 내적 명령을 사용한다.
- Tensor Core는 전용 행렬 타일 MMA 유닛이고, NPU는 신경망 특화 가속기 범주다.
- 제품 세대·정밀도·데이터 이동·호출 비용을 맞춰야 공정한 성능 비교가 된다.
- 현재 코드는 Python CPU 반복문이며 실제 가속기 성능 측정 프로그램은 아니다.
