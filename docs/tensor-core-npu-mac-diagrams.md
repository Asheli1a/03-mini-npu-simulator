# 도식으로 이해하는 텐서 코어와 NPU의 MAC 가속 원리

텐서 코어와 NPU는 MAC을 새로운 수학으로 계산하는 것이 아니라, 곱하고 더하는 회로를 병렬로 배치하고 데이터를 가까이에서 재사용해 가속한다. 계산기를 많이 두는 것뿐 아니라 계산기에 숫자를 공급하는 방식까지 최적화하는 것이 핵심이다.

이 문서의 그림은 동작 원리를 설명하기 위해 단순화한 기능도다. 실제 칩의 배선도나 회로 배치를 재현한 것은 아니다. 텐서 코어는 NVIDIA GPU를, NPU의 데이터 흐름은 구조가 공개된 Google TPU를 대표 사례로 사용한다. 모든 NPU가 TPU와 같은 구조라는 뜻은 아니다.

## 1. 먼저 비교 대상을 구분한다

| 구분 | 텐서 코어 | NPU |
|---|---|---|
| 범주 | NVIDIA GPU 내부의 행렬 연산 전용 실행 장치 | 신경망 처리를 특화한 가속기 범주 |
| 구성 관점 | GPU의 메모리·제어 체계와 협력하는 계산 부품 | 연산기·메모리·제어기 등을 포함한 가속기 |
| 공통 원리 | 다수의 MAC, 데이터 재사용, 적합한 정밀도 활용 | 같은 원리를 활용하되 제품별 구조는 다름 |

따라서 텐서 코어와 NPU를 동일한 크기의 독립된 부품처럼 비교하지 않는다. CPU와 일반 GPU 연산기도 MAC을 수행할 수 있다. 차이는 어떤 연산을 얼마나 효율적으로 묶어 실행하도록 설계했는가에 있다. [NVIDIA GPU 실행 구조](https://docs.nvidia.com/deeplearning/performance/dl-performance-gpu-background/index.html), [Google TPU 구조](https://docs.cloud.google.com/tpu/docs/system-architecture-tpu-vm)

## 2. MAC 회로 하나: 곱하고 이전 합계에 더한다

MAC(Multiply-Accumulate)은 `s ← s + x × w`를 반복한다. x는 입력, w는 가중치, s는 중간 합계다.

```text
입력 x ------+
             v
          [곱셈기] -----> [덧셈기] -----> [합계 저장소]
             ^                ^                |
가중치 w ----+                +----------------+
                                이전 합계 s
```

곱셈기는 두 숫자의 곱을 만들고, 덧셈기는 그 값을 이전 합계에 더한다. 합계를 회로 가까이 보관하면 매번 외부 메모리에 쓰고 다시 읽는 일을 줄일 수 있다. 실제 하드웨어에서는 곱셈과 덧셈이 더 긴밀하게 결합될 수 있으며, 이 그림이 곱셈과 덧셈 사이의 별도 반올림을 뜻하지는 않는다.

예를 들어 `2×5 + 3×6 + 4×7`은 다음처럼 계산한다.

```text
처음 합계:  0
첫 MAC:    0 + 2×5 = 10
둘째 MAC: 10 + 3×6 = 28
셋째 MAC: 28 + 4×7 = 56
```

신경망은 이런 가중합을 수많은 출력에 대해 수행한다. 여러 입력과 출력의 계산을 묶으면 행렬곱으로 나타낼 수 있다. [행렬곱과 신경망 연산](https://docs.nvidia.com/deeplearning/performance/dl-performance-matrix-multiplication/index.html)

## 3. 빠르게 계산하려면 숫자 공급도 빨라야 한다

작업자가 1,000명이어도 재료를 한 명씩만 받을 수 있다면 대부분은 기다린다. 계산 회로도 데이터를 공급받지 못하면 놀게 된다. 따라서 병렬 연산기와 데이터 재사용을 함께 설계해야 한다.

다음은 입력 세 개로 출력 두 개를 만드는 예다.

```text
출력 1 = x1×w11 + x2×w21 + x3×w31
출력 2 = x1×w12 + x2×w22 + x3×w32
```

입력 x1은 두 출력 모두에 필요하다. x1을 가까운 저장소에 두거나 인접 연산기로 넘기면 같은 값을 외부 메모리에서 두 번 가져올 필요를 줄일 수 있다. 여러 입력을 연속 처리할 때는 가중치도 재사용할 수 있다. 이처럼 행렬곱은 입력과 가중치의 재사용 기회가 많다. [공유 메모리와 타일을 이용한 텐서 코어 데이터 재사용](https://developer.nvidia.com/blog/using-tensor-cores-in-cuda-fortran/)

## 4. 텐서 코어: 작은 행렬 블록을 전용 회로로 계산한다

텐서 코어가 수행하는 대표 연산은 `D = A × B + C`다. A·B·C·D는 작은 숫자 배열이다. 여기서 곱셈은 같은 위치끼리 곱하는 원소별 곱이 아니라, 행과 열의 내적으로 여러 출력을 만드는 행렬곱이다. [NVIDIA Volta 아키텍처](https://images.nvidia.com/content/volta-architecture/pdf/volta-architecture-whitepaper.pdf)

### GPU 내부에서의 위치

다음은 Ampere 등에서 이해하기 쉬운 대표 경로를 단순화한 그림이다. 실제 저장 위치와 데이터 전달 경로는 세대·명령에 따라 다르다.

```text
GPU
+------------------------------------------------------+
| 외부 GPU 메모리: GDDR 또는 HBM                       |
|                       |                              |
|                    [L2 캐시]                         |
|                       |                              |
|  +--------------------v---------------------------+  |
|  | SM: GPU 내부 처리 블록                         |  |
|  |                                                |  |
|  | [공유 메모리: 여러 작업이 쓸 숫자 블록 보관]   |  |
|  |                       |                        |  |
|  |                  [레지스터]                    |  |
|  |                    |      |                    |  |
|  |            +-------v--+ +-v-----------------+  |  |
|  |            | CUDA 코어| | 텐서 코어         |  |  |
|  |            | 범용 연산| | 행렬곱·누산 전용 |  |  |
|  |            +----------+ | D = A×B + C       |  |  |
|  |                         +-------------------+  |  |
|  +------------------------------------------------+  |
|                    이런 SM이 여러 개                 |
+------------------------------------------------------+
```

GPU 프로그램은 큰 행렬을 작은 블록인 타일로 나누고, 가까운 저장소에 가져온 데이터를 여러 번 사용하면서 행렬 연산을 진행한다. CUDA 코어와 텐서 코어가 각각 자기 전용 외부 메모리를 가진다는 뜻은 아니다. [A100 아키텍처와 텐서 코어](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/nvidia-ampere-architecture-whitepaper.pdf), [GPU 메모리 계층](https://docs.nvidia.com/deeplearning/performance/dl-performance-gpu-background/index.html)

### 무엇이 가속되는가?

1. 여러 가중합을 병렬 처리한다. 행렬 블록에 필요한 많은 곱셈·누산을 전용 실행 장치로 처리한다.
2. 명령과 데이터 접근의 부담을 줄인다. 행렬 연산 단위로 계산을 묶고, 여러 계산에서 입력과 가중치를 재사용한다.
3. 적절한 숫자 형식을 사용한다. 예를 들어 FP16 입력과 FP32 누적을 조합할 수 있다. 작은 형식의 입력으로 처리량을 높이면서 누적 오차를 관리하는 방식이다.

A100 백서는 행렬 명령의 계산 범위 확대와 데이터 공유를 통한 중복 레지스터 접근 감소를 설명한다. 단순히 곱셈 회로만 늘린 것이 아니라 계산을 준비하고 공급하는 부담도 줄인 것이다. 입력을 낮은 정밀도로 바꾸면서 이미 잃은 정보는 더 높은 정밀도로 누적한다고 복구되지는 않는다. [A100 아키텍처](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/nvidia-ampere-architecture-whitepaper.pdf)

최초 Volta의 설명에 등장하는 4×4×4 행렬 곱셈-누산을 예로 들면, 출력 16개 각각에 4 MAC이 필요하므로 총 64 MAC이다. 이는 특정 구조의 연산 묶음 예이지 모든 세대의 고정 규격이 아니다. 프로그램의 행렬 명령 하나가 항상 1클록에 완료된다는 뜻도 아니다. [Volta 아키텍처](https://images.nvidia.com/content/volta-architecture/pdf/volta-architecture-whitepaper.pdf)

최신 구조를 위 도식에 그대로 대입하지 않는다. 예를 들어 Blackwell의 tcgen05 계열은 누적값 등에 전용 Tensor Memory를 사용한다. [Blackwell 행렬 명령과 Tensor Memory](https://docs.nvidia.com/cutlass/latest/media/docs/pythonDSL/guides/mma/tcgen05_programming.html)

## 5. NPU: 계산 배열과 데이터 이동을 함께 설계한다

NPU는 MAC 배열만 있는 장치가 아니다. 배열에 입력과 가중치를 공급하고 중간 결과를 보관하는 메모리, 전송 장치, 제어기 등이 함께 필요하다. 다음은 TPU 사례를 바탕으로 기능을 나눈 개념도다. 실제 제품에서는 각 기능의 이름과 경계가 다를 수 있다. [TPU 구조](https://docs.cloud.google.com/tpu/docs/system-architecture-tpu-vm)

```text
                CPU / 실행 프로그램
                         |
                         v
+---------------- NPU / AI 가속기 ------------------+
|                                                   |
| [제어 및 데이터 전송]                             |
|             |                                     |
|             v                                     |
| [칩 내부 버퍼: 입력·가중치·중간 결과 보관]        |
|             |                         ^           |
|             v                         |           |
| [MAC / 행렬 연산 배열] ------> [벡터·후처리 장치] |
|             |                                     |
| [가까운 누적 저장소]                              |
+---------------------------------------------------+
                         |
                         v
                  외부 메모리 / HBM 등
                   (실제 전송은 양방향)
```

외부 메모리는 큰 창고, 칩 내부 버퍼는 작업대 옆 재료함, MAC 배열은 생산라인에 해당한다. 작업대 가까이에서 숫자를 재사용하면 큰 창고를 왕복하는 부담이 줄어든다.

### 시스톨릭 배열: 옆 연산기로 숫자를 전달한다

Google TPU는 서로 연결된 연산 셀의 격자인 시스톨릭 배열을 사용한다. 일정한 박자에 따라 데이터와 중간 결과가 배열을 통과한다. 다음은 가중치를 각 셀에 미리 보관하고 입력은 가로로, 부분합은 세로로 전달하는 방식을 단순화한 예다. 실제 TPU의 모든 세대·내부 배선을 그대로 재현한 그림은 아니다. [TPU의 시스톨릭 배열](https://docs.cloud.google.com/tpu/docs/system-architecture-tpu-vm)

```text
                  부분합 0            부분합 0
                     |                   |
                     v                   v
입력 x1 ------> [셀: w11] ---------> [셀: w12] ------>
                     |                   |
                     v                   v
입력 x2 ------> [셀: w21] ---------> [셀: w22] ------>
                     |                   |
                     v                   v
입력 x3 ------> [셀: w31] ---------> [셀: w32] ------>
                     |                   |
                     v                   v
                   출력 1              출력 2

가로: 입력값 전달
세로: 부분합 전달
각 셀: 새 부분합 = 이전 부분합 + 입력 × 저장된 가중치
```

출력 1은 왼쪽 열에서 `x1×w11 + x2×w21 + x3×w31`로 만들어진다. 같은 입력은 오른쪽 셀로 이동해 출력 2 계산에도 사용된다. 중간 합계를 매번 외부 메모리에 쓰고 읽지 않고 인접 셀로 전달한다.

실제로는 해당 입력과 부분합이 같은 시점에 만나도록 입력 투입 시간을 어긋나게 맞춰야 한다. 위 도식은 이 시간차와 내부 레지스터를 생략했다. 새로운 입력 묶음을 연속 투입하면 배열이 채워진 뒤 서로 다른 작업이 여러 셀에서 겹쳐 진행된다. 첫 결과가 즉시 나오는 것은 아니며, 배열을 채우고 비우는 시간도 있다.

핵심은 각 MAC마다 외부 메모리를 왕복하지 않는다는 점이다. 최초 입력과 가중치를 가져오고 최종 결과를 저장하는 전송까지 없어지는 것은 아니다. [TPU의 데이터 흐름](https://docs.cloud.google.com/tpu/docs/system-architecture-tpu-vm)

## 6. 공통점과 차이 정리

| 가속 원리 | 텐서 코어에서의 모습 | TPU 같은 NPU 사례 |
|---|---|---|
| 연산 병렬화 | 여러 실행 장치가 행렬 타일 처리 | 격자의 다수 MAC 셀이 동시 계산 |
| 데이터 재사용 | 공유 메모리·레지스터 등에서 재사용 | 셀 사이 전달과 가까운 버퍼 활용 |
| 중간 합계 유지 | 레지스터 또는 세대별 전용 저장소 | 셀·누적 저장소·인접 셀 전달 |
| 제어 부담 감소 | 행렬 명령에 다수 연산을 묶음 | 규칙적인 데이터 흐름으로 배열 운용 |

텐서 코어는 병렬 처리만 하고 NPU는 데이터 재사용만 하는 것이 아니다. 양쪽 모두 병렬 계산과 재사용을 활용한다. 또한 텐서 코어의 공개된 행렬 연산 기능만 보고 내부 회로가 위 시스톨릭 개념도와 동일하다고 단정하지 않는다. [A100 아키텍처](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/nvidia-ampere-architecture-whitepaper.pdf), [TPU 구조](https://docs.cloud.google.com/tpu/docs/system-architecture-tpu-vm)

## 7. Mini NPU Simulator와 연결하기

이번 프로그램의 핵심은 다음 코드다.

```python
score += pattern[row][column] * filter_matrix[row][column]
```

이 코드는 같은 위치의 입력과 필터 값을 곱해 누적한다. 필터 하나의 N×N 점수를 계산하면 N² MAC이며, 같은 순서로 펼친 두 벡터의 내적과 같다. 학습으로 가중치를 갱신하거나 실제 NPU에서 실행하는 것은 아니다. 구현·검증·측정 기록은 [README](../README.md)에 정리했다.

```text
현재 실습
원소를 차례로 방문해 필터 하나의 점수를 계산
                         |
                         v
가속기에서 활용하는 계산 구성
여러 입력 × 여러 필터의 점수를 행렬곱으로 묶음
                         |
                         v
같은 입력·가중치를 재사용하며 수많은 MAC을 병렬 실행
```

1차원 평탄화는 자료 접근 방식을 바꾸는 작업이며, 그 자체로 텐서 코어나 NPU가 사용되는 것은 아니다. 작은 계산에서는 준비·변환·전송·실행 요청 비용이 계산 시간 감소보다 클 수 있다. 행렬 크기와 데이터 재사용을 고려해야 하며, 장치의 최고 연산 성능으로 전체 실행 속도를 바로 예측하지 않는다. [GPU의 연산·메모리 성능 관점](https://docs.nvidia.com/deeplearning/performance/dl-performance-gpu-background/index.html)

Python 반복문에서 세는 MAC은 알고리즘상의 연산 횟수다. 실제 명령 수·클록 수와 같지 않으며, Python의 곱셈 뒤 덧셈이 단일 반올림의 하드웨어 FMA와 동일하다는 뜻도 아니다. 신경망에는 활성화·정규화 등 다른 계산도 필요하다.

## 8. 내 말로 설명하기

> 텐서 코어와 NPU는 계산기를 많이 놓는 것에서 그치지 않고, 숫자를 가까이 보관하고 옆 계산기로 전달하는 생산라인을 만든다. 여러 곱셈과 덧셈을 동시에 처리하면서 같은 숫자를 반복 운반하는 일을 줄이므로 대규모 MAC을 효율적으로 수행한다. 현재 실습은 이 생산라인 전체가 아니라 그 기본 작업인 곱셈·누산을 Python 반복문으로 구현한 것이다.

배경은 [AI 발전사와 MAC](ai-history-and-mac.md), CPU SIMD·Pascal CUDA와의 비교 및 공정한 측정 조건은 [기존 하드웨어 가속 문서](mac-hardware-acceleration.md)로 연결한다. 이 문서는 설명 자료이며 기존 코드·원본 데이터·판정 정책·성능 측정 결과를 변경하지 않는다.
